1. Business objective

Let a plan sponsor find a covered member in the SponsorConnect member directory by searching, instead of scrolling a full list, and download the filtered directory as a spreadsheet for their own reconciliation.

Sponsor administrators reconcile their payroll records against MapleSure's member directory every month. Today the directory is a single unfiltered list, so a sponsor with a large workforce scrolls page after page or phones the service desk to confirm one member's coverage.

2. Background and current state

  • The SponsorConnect Portal already shows a member directory (/members) and a member detail page, reading all data from the claims API. Nothing changes in what data is shown — only how a sponsor gets to it.
  • The directory has no search, no filter and no export. Sponsors copy names by hand into their own spreadsheets.
  • The service desk receives "is this employee covered?" calls that a simple search would answer.

3. Requirements

  1. Search box. The member directory page has a search box; typing a member's surname, given name or member ID and pressing Enter (or the Search button) narrows the list to matching members.
  2. Partial and case-insensitive matching. Search matches on any part of the name or member ID and ignores letter case, so "mor" finds "Moreau" and "MOREAU".
  3. Coverage status filter. A filter lets the sponsor show all members, only active members, or only members whose coverage has ended.
  4. Result count and empty state. The page states how many members match ("12 of 340 members"), and a search with no matches says so plainly with a "Clear search" link.
  5. Export to CSV. A "Download CSV" button exports the members currently shown — respecting the active search and filter — with columns member ID, surname, given name, plan, coverage status, coverage start date. Nothing beyond what the directory already displays is exported.
  6. Sponsor scope only. Search and export return only members of the signed-in sponsor's own plans — never members of another sponsor.
  7. Export is logged. Each CSV download is recorded (sponsor, timestamp, row count) so exports can be reviewed later.
  8. Accessibility. The search box, filter and download button are keyboard-accessible and labelled; the result count is announced to screen readers when it changes.

4. Out of scope

  • Editing member records or adding members from the portal — the directory stays read-only.
  • Any change to the claims API's data model; the portal continues to read the fields it already receives.
  • Scheduled or emailed exports; this release is on-demand download only.

5. Success measures

  • A sponsor can find a named member in the directory in one search.
  • The CSV a sponsor downloads contains exactly the members shown on screen at the time, and never a member of another sponsor.
  • Reduction in "is this employee covered?" calls to the service desk in the first month after release.

6. Notes for delivery

This is a small change to one existing page and one new download route in the SponsorConnect Portal. Keep it that way: no new application, no new data store, synthetic member data only.
