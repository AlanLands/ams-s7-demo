New immutable review package; prior result preserved.

No phase self-approves. The evidence changes, the review version changes, and the full history remains traceable.
BEYOND THIS RUN Target design · not yet built

The correction loop fixes this run. This is the loop that fixes the next one.

A human correction shouldn't just patch one story — it should teach the agent that produced it, the same way a senior engineer corrects a junior developer.

STEP 1
AI output

An agent generates code, a story, or a config from its current skill file.

STEP 2
Human edits it

A developer corrects it in their own IDE — the same commit that unblocks the story.

STEP 3
Signal, not silence

The diff between generated and shipped is captured, not quietly accepted.

STEP 4
Skill amendment

Recurring corrections roll into a versioned change to the agent's skill file, ledgered with the diffs that triggered it.

STEP 5
Next run needs no human

The agent applies the amendment itself — that class of correction stops reaching the gate.

Just like teaching a developer. Correct it once, name why, and it doesn't happen again. The skill file is the durable memory — not a one-off prompt edit the next run has already forgotten.
Autonomy is earned, not assumed. Checkpoints loosen only where the first-time-right rate holds up across many runs — today, every AI output is still reviewed by a human, on every run.

GOVERNANCE · TRACEABILITY · METRICS

Every claim in the dashboard should resolve to evidence

Traceability

Requirement → Plan → Architecture → Pack → Story → Task → Commit → PR → Test → Review → Quality.

Version + staleness

Architecture or plan revisions mark downstream packs, tasks and evidence stale until refreshed or explicitly excepted.

Provenance

Artifact version, SHA-256 hash, producer, timestamp and input references are append-only.
