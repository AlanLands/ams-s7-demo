# Engineering Excellence Expo 2026

Submission and presentation material for **Control Center — Governed
AI-Assisted SDLC**. Everything here is authoring output, not demo runtime:
nothing under `docs/EXPO/` is imported by `s7_delivery/` or either app.

## Presenting

Start at [`presentation/presenter-script.md`](presentation/presenter-script.md) —
run sheet, fallbacks and the Q&A crib.

**Present from the silent set. Send the narrated set.**

| File | What it is |
|---|---|
| `presentation/expo-deck.html` | **The deck to present.** 9 slides in the browser, with speaker notes and a presenter window (P) and five generated detail views. It needs `expo-deck-assets/` beside it; `make_portable.py` writes a single-file copy. |
| `presentation/expo-10min.pptx` | 13 slides for the 10-minute slot, short film on slide 6 — the earlier PowerPoint version |
| `presentation/expo-detailed.pptx` | 35 slides, long film on slide 13 — walkthrough or leave-behind |
| `video-short/renders/video-short.mp4` | 2:49 · 1920×1080 · 30 fps |
| `video-detailed/renders/video-detailed.mp4` | 5:12 · 1920×1080 · 30 fps |
| `expo-case-study.md` / `.docx` | The two-page submission form |

Both decks carry speaker notes on every slide.

### The narrated set — for sending, not presenting

Same visuals, with a spoken narration written for someone who joined the team
this week: every term defined on first use, one idea per sentence. Send these
when you are not in the room to talk over them.

| File | What it is |
|---|---|
| `video-short/renders/video-short-narrated.mp4` | 2:49, your voice, word-synced captions |
| `video-detailed/renders/video-detailed-narrated.mp4` | 5:12, your voice, word-synced captions |
| `presentation/expo-10min-narrated.pptx` | Narration on every slide, advances itself |
| `presentation/expo-detailed-narrated.pptx` | Same, 35 slides |
| `narration/captions-*.srt` | The subtitle files, also muxed into the films |

The two narrated **films** are the safe choice: the voice and the captions are
baked into the MP4, so they play anywhere with nothing to configure.

The narrated **decks** embed a clip per slide set to start on its own, with the
slide transition timed to it. PowerPoint is not installed on the build machine,
so that XML is verified structurally and not by watching it play — **click
through one once on the machine you will send it from.** The film slide
deliberately waits for a click rather than sequencing two media players in one
slide's timing tree. Every clip stays clickable, so the deck is still usable if
a viewer's PowerPoint declines to autostart.

**The story they tell.** Three beats, identical across all four artifacts:
today every developer brings their own context and the same story produces
three different implementations; the platform answers with one governed pack of
*files* rather than advice; upstream agrees what done means and downstream
builds until it is provably done, with five gates, each signed by a named human, and
no phase approving its own work. The worked example — 30 days, 5 attempts, 15 minutes — runs
through all of it.

## How it is built

**Decks** are generated by `python-pptx`, not hand-edited — edit the build
script and rebuild, or the next build overwrites your changes.

- `presentation/deckkit.py` — slide primitives (cards, tiles, badges, icon
  tiles, personas, artifact chips, governed lanes, screenshot frames), plus the
  seven-colour accent family shared with the films. `card()`, `quote()`,
  `rows()`, `table()` and `persona()` all measure their own content and raise at
  build time rather than shipping an overlap; a card's icon sits top-right so it
  costs no height.
- `presentation/render_icons.js` — renders the films' icon set to PNGs (one per
  icon per accent) so slides and films share one icon language.
- `presentation/build_10min.py`, `presentation/build_detailed.py` — content.
- `presentation/audit_deck.py` — checks every shape sits inside the slide, that
  nothing intrudes on the footer band, and that no text box is obviously too
  small for its text. Run it after any edit.
- `presentation/preview_deck.py` — renders a generated `.pptx` back to an HTML
  contact sheet from the real file, for eyeballing layout without PowerPoint.

**Films** are HyperFrames compositions rendered offline.

- `video-*/index.html` — the top-level composition; scenes live in
  `compositions/` and are loaded via `data-composition-src`.
- `video-*/runtime.js` — a small HyperFrames-compatible runtime: the
  `window.__timelines` registry, composition loading, automatic nesting of
  sub-timelines by `data-start`, clip mount/unmount, and `window.SEEK(t)` /
  `window.DURATION` for the renderer.
- `video-*/render.js` — serves the project on loopback and steps `SEEK` frame by
  frame through `chrome-headless-shell`, then encodes with ffmpeg. Same standing
  as `demo/render_pdf.py`: authoring tooling, not demo runtime.
- `video-*/icons.js` — 24 flat stroke icons as inline SVG, `currentColor`, so an
  icon takes the accent of the tile it sits in. No sprite file, no network.
- `video-*/theme.css` — the Control Centre's own palette and Source Sans 3 plus
  the accent family, Liquid Glass surfaces (`backdrop-filter`, specular sheen)
  and the drifting aurora that gives the glass something to refract. Surfaces
  stay at or above 78% opacity so text contrast survives at 1080p.
- `video-*/vendor/` — gsap and the font, vendored. No CDN, nothing fetched at
  render time.
- `video-*/assets/` — the real application screenshots from run S7-00002, copied
  from `docs/presenter-guides/screenshots/`.

Rendering is deterministic: no `Math.random()`, no clock reads on the render
path, so the same composition produces the same frames every time.

```sh
node video-short/render.js --fps 30        # 5,160 frames
node video-detailed/render.js --fps 30     # 9,540 frames
```

`--start` and `--end` render a slice while iterating on one scene. `render.js`
needs `puppeteer-core` on `NODE_PATH`; it is authoring-only and deliberately not
a repo dependency.

**Narration** is the presenter's own cloned voice, through ElevenLabs. This is
the one place the material reaches the network, and it is authoring-only —
nothing under `docs/EXPO/` is imported by `s7_delivery/` or either app, so no
network call lands on a path the product runs. Hard rule 3 still applies: the
key lives in the repo's gitignored `.env` and is never printed or committed.

The pipeline runs in this order, because each step depends on the one before:

```sh
python narration/build_narration.py short --plan     # synthesise, measure
python narration/compose_film.py short               # re-time + caption data
node video-short/render.js --fps 30 --captions 0 --out video-short
node video-short/render.js --fps 30 --captions 1 --out video-short-captioned
python narration/build_narration.py short --mux      # voice onto the captioned cut
python presentation/build_narrated.py both           # narrated deck copies
```

**The words come first and the scenes stretch to hold them** — never shrinking
below the length an animation was designed for. The earlier arrangement was the
reverse, fitting lines into fixed windows, which cost several of them a clause.

- `narration/eleven.py` — TTS with **character-level timestamps**, which is what
  makes word-synced captions possible; guessing word times by dividing a clip
  across its letters drifts the moment a voice pauses. Every render is cached
  under `narration/cache/` keyed by a hash of text, voice, model and settings,
  so a re-render is not a re-spend and the films stay reproducible — the same
  discipline `common/llm.py` records in § Determinism. It refuses to return
  timings that do not match the script, rather than letting captions desync.
- `narration/tts.py` — the macOS `say` fallback, for when there is no key. It
  yields no timings, so that path gets sentence-level captions only. It also
  bounds the wait on `say`, which intermittently writes a complete file and then
  never exits.
- `narration/script-*.json` — one line per film scene; `deck-*.json`, one per
  slide. The deck and the films share a voice on purpose.
- `narration/compose_film.py` — re-times scenes, alternates tracks so adjacent
  scenes may overlap and cross-dissolve, adds the slow push-in, and writes
  `captions-data.js` in film time. Idempotent: re-running with the same timings
  reproduces the same `index.html` byte for byte.
- `presentation/build_narrated.py` — the narrated deck copies. It re-opens what
  it wrote and refuses to finish if the autostart node points at a shape that is
  not there, the icon covers slide content, or a slide's auto-advance is set the
  wrong way round.

**Each film is rendered twice** — `--captions 0` for the cut you present over,
`--captions 1` for the narrated cut. This ffmpeg has no libass, so captions
cannot be burned in afterwards; they have to come from the page.

To change voice, set `ELEVENLABS_VOICE_ID` in `.env` (or pass `--voice`) and
re-run from `--plan`: a different voice means different timings, so the films
must be re-rendered, not just re-muxed. `narration/samples/` holds one line in
the current voice and one in the offline fallback, for comparison.

`compose_film.py` writes its block between sentinel comments and replaces
exactly that span, so re-running it is a no-op — worth keeping, because the
renderer reads `index.html` and a build that quietly appended a second copy of
its own output each time went unnoticed until the file was diffed against
itself.

## Content rules

Every figure shown comes from the run ledgers or the case study. MapleSure
Insurance is fictional and all data is synthetic (hard rules 1 and 2). Where a
number cannot be evidenced the material says "not measurable" and gives the
reason rather than filling the cell — the same discipline the product applies to
its own KPI scorecard.

`IMG_*.JPG` are the original submission photographs and are not used by the
decks or the films.
